Architectural Philosophy

Why A Naive Script Fails in Production

Most MCP servers are 30-line demo wrappers that fail under real model behavior. VaultMCP was built as a hardened system engineering solution addressing the four critical vulnerabilities of LLM file access.

1. Strict Path Confinement (Zero-Trust)

LLMs cannot be trusted with relative path strings. Prompts frequently generate traversal attempts (`../../`), symlink loops, or Windows drive root escapes.

VaultMCP Solution: Canonical os.path.realpath() resolution against vault root. Raises PathConfinementError before any file handle is acquired.

2. Section-Level AST & BM25 vs. Document Dumping

Dumping 5,000-line Markdown documents into an LLM context window increases latency by 10x, drains token budgets, and causes "lost in the middle" hallucinations.

VaultMCP Solution: Full Markdown AST section parser. SQLite FTS5 stores passages weighted by heading level (H1: 10x • H2: 5x • H3: 2x). Sub-10ms response.

3. Non-Destructive Scoped Writes & Backups

Accidental file clobbering or unauthorized modification of personal notes destroys user trust. Unconstrained writes can corrupt years of interconnected knowledge.

VaultMCP Solution: Writes disabled by default. Scoped strictly to designated folders (`inbox/`). Automated pre-write backup snapshot prior to append. Zero deletion tool exists.

4. Guaranteed Stdout Framing Purity

Desktop MCP clients (Claude Desktop, Cursor) read raw JSON-RPC over `stdio`. A single stray `print()` or third-party logger corrupts stream framing and terminates the connection.

VaultMCP Solution: Strict stdout reservation. Custom logging setup diverts 100% of debug logs, diagnostic output, and tracebacks to `stderr`. Verified by automated test.

System Design

        

          Engineered for Extreme Reliability
        

        

          A decoupled, layered design that separates transport handling, security enforcement, indexing, and persistent storage.
        

      


      
      

        

          
          

            
1. Ingress Layer

            
Dual Transports

            

              Standard Stdio for local IDEs (Claude Desktop, Cursor). Streamable HTTP SSE with constant-time SHA-256 Bearer Token verification for remote agent clusters.
            

          


          

            
2. Security Sandbox

            
Confinement & Scopes

            

              Realpath boundary checks prevent any escaping access. Scoped tokens enforce read vs read_write permissions. All writes restricted to designated folders.
            

          


          

            
3. Storage Engine

            
SQLite FTS5 + WAL

            

              Full-text BM25 index with heading boosts. Incremental SHA-256 scanner tracks file updates. Timestamped pre-write backup engine archives every modification.
